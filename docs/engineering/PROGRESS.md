## Known issues and tech debt

- Product code so far: the M1 scaffold, the M2 contracts and the M3 database layer (no features yet).
- **Local S3 is RustFS 1.0.6** (chosen in M3 under ADR-022, 24 Nov 2026). It's Apache-2.0, actively released (1.0.0 on 16 Sep 2026, then six releases to 1.0.6 on 15 Nov), started here in one container with no setup, and takes its keys from environment variables. It is young: 1.0 is about two months old. MinIO's repository is archived. Chainguard's MinIO image was ruled out on a wrong reading of an HTTP 401: it can be pulled without an account (checked again the same day), and it was not compared further. Garage was not tried. Fallback: SeaweedFS (Apache-2.0, repository since 2014, about weekly releases). Nothing uses S3 before T2.3, whose tests must prove presigned PUT, multipart upload and CORS against it; if they fail, swap the compose service (code only uses the S3 API).
- **Migrations are drizzle-kit `generate` only:** never `drizzle-kit push` or `pull`, which compare against a live database and would try to drop the hand-written parts (PLAN.md §3.4). A schema change without a migration fails `src/schema.test.ts`.

On this machine (Windows 11, Docker Desktop) a run takes about 10 s with the image already pulled (measured 24 Nov 2026).
